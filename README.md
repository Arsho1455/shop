# PhoneShop — նոր դիզայն + ArmaAuth + անձնական զամբյուղ

Այս նախագիծը միավորված **PhoneShop** կայքն է՝ React/Vite Frontend-ով և Express/MongoDB Backend-ով։ Գլխավոր էջը, կատալոգը, ապրանքի էջը, Header-ը, Footer-ը և Contact էջը վերադիզայնվել են։ **Favorites-ն ու Cart-ը տեղափոխվել են օգտագործողի անձնական էջ** և պահպանվում են MongoDB-ում՝ յուրաքանչյուր հաշվի համար առանձին։

## 🌐 Կայքի լեզուներ — Հայերեն / Русский / English

Header-ի աջ կողմում ավելացվել են **ՀԱՅ · РУС · ENG** ընտրության կոճակներ՝ համակարգչի և հեռախոսի համար։
Ընտրված լեզվով թարգմանվում են գլխավոր էջը, նավիգացիան, ապրանքի էջերը, ապրանքի նկարագրություններն ու պիտակները, զամբյուղը, նախընտրածները, անձնական էջը, մուտքը, գրանցումը, email-ի հաստատման էջը և Contact ձևը։
Գրանցման հաստատման նամակն ուղարկվում է **գրանցման պահին ընտրված լեզվով** (Nodemailer)։

- Լեզվի փոփոխությունը կատարվում է անմիջապես՝ առանց էջը վերաբեռնելու կամ օգտատիրոջ հաշիվը կորցնելու։
- Ընտրված լեզուն պահվում է browser-ի `localStorage`-ում (`phoneshop-language`) և պահպանվում է կայքը փակելուց հետո։
- Սկզբնական լեզուն հայերենն է։
- Կոդը՝ `Client/src/i18n/LanguageContext.jsx`, `Client/src/i18n/translations.js`։ Նոր տեքստերի թարգմանությունները լրացրու `translations.js`-ում։
- Բոլոր լեզուների դեպքում գները ցուցադրվում են **AMD (֏)**-ով։
- Email-ի հաստատման հղումն ունի անվտանգ `?lang=` պարամետր, որ բացվելուց հետո լեզուն համընկնի ուղարկված նամակի հետ։

## Օգտագործման տրամաբանություն

- Առանց մուտք գործելու հնարավոր է բացել գլխավոր էջը, դիտել և որոնել ապրանքներ, բացել ապրանքի էջերը։
- Ապրանքի **♡** կամ **«Ավելացնել զամբյուղ»** կոճակները սեղմելիս, եթե մուտք գործած չես, բացվում է `/auth?mode=login`՝ գրանցման տարբերակով։ Մուտք գործելուց հետո վերադարձնում է այն էջը, որտեղից եկել էիր. **ապրանքն ինքնաբար չի ավելացվում**, նորից պետք է սեղմես կոճակը։
- Header-ում կա միայն **«Մուտք / Գրանցում»** / **«Իմ էջը»** կոճակը։ Առանձին Cart / Favorites կոճակներ Header-ում չկան։
- `/profile` — անձնական տվյալներ, `/profile/favorites` — նախընտրածներ, `/profile/cart` — զամբյուղ։ Բոլորն աշխատում են միայն մուտք գործած օգտատիրոջ համար։
- Նախընտրածներն ու զամբյուղը պահվում են օգտատիրոջ `users` գրառման մեջ (`favorites`, `cart`)։ Մեկ հաշվի ապրանքները մյուս օգտատերը **չի տեսնում**։ Հյուրի տվյալներ `localStorage`-ում չեն պահվում։
- Ավելացնել/հեռացնել, քանակը փոխել, զամբյուղը մաքրել՝ աշխատում են Express API-ով և MongoDB-ով։
- Գրանցում / Email confirmation / Մուտք — bcrypt, JWT HttpOnly cookie, Nodemailer (նախկին ArmaAuth տրամաբանությունը)։
- **Contact էջը** անմիջապես ուղարկում է նամակ Backend API-ով և Nodemailer-ով։ Օգտատերը լրացնում է անուն, email, հաղորդագրություն, և Gmail/այլ email ծրագիր չի բացվում։ Գրանցված լինելը պարտադիր չէ։
- **Իրական վճարման և պատվերի հաստատման համակարգ չկա**։ Cart-ը պահեստավորում է ընտրված ապրանքները և հաշվում գումարը, բայց պատվեր չի ձևակերպում։

## Պատրաստիր .env ֆայլերը

### `Server/.env`

`Server/.env.example`-ը պատճենիր `Server/.env`։ Եթե արդեն կա **քո սկզբնական** Shop.project-ի `.env`-ը, տեղադրիր այն այստեղ և ավելացրու JWT գաղտնիքը։ Գաղտնի տվյալները անվտանգության համար ZIP-ում չեն պահվել։

```env
PORT=3000
MONGO_URL=mongodb://127.0.0.1:27017
JWT_SECRET=PUT_A_RANDOM_SECRET_AT_LEAST_32_CHARACTERS_HERE
FRONTEND_URL=http://localhost:5173
send_mail=you@gmail.com
send_mail_password=YOUR_GOOGLE_APP_PASSWORD
CONTACT_TO_EMAIL=your-business-email@gmail.com
```

- `MONGO_URL`-ի փոխարեն աշխատում է `MONGODB_URI`։
- `send_mail`-ի փոխարեն՝ `SMTP_USER`; `send_mail_password`-ի փոխարեն՝ `SMTP_PASS`։
- Gmail-ի համար պետք է **App Password**, ոչ թե սովորական հաշվի գաղտնաբառ։ Այլ SMTP-ի համար կարող ես նշել `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`։
- `CONTACT_TO_EMAIL` — քո հասցեն, որին պետք է հասնեն Contact էջի նամակները։ Եթե բաց թողնես, կօգտագործվի `send_mail` / `SMTP_USER`։ `SMTP_USER`-ը **ուղարկող** Gmail-ն է, `CONTACT_TO_EMAIL`-ը՝ **ստացողը**։
- Նամակի `Reply-To`-ը ավտոմատ կլինի հաճախորդի մուտքագրած հասցեն, այսինքն՝ Gmail-ում «Պատասխանել» (Reply) սեղմելիս կպատասխանես հաճախորդին։
- SMTP-ի արժեքները պահիր միայն **Server/.env**-ում։ **Երբեք** մի գրիր SMTP գաղտնաբառը Client-ում։
- `JWT_SECRET`-ը գեներացրու օրինակ հրամանով՝ `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`։
- `FRONTEND_URL`-ը պետք է համընկնի բացած կայքի origin-ին (`http://localhost:5173`), որ CORS-ն ու cookie-ն աշխատեն։

### `Client/.env`

```env
VITE_API_URL=http://localhost:3000
```

`VITE_CONTACT_EMAIL`-ն այլևս պետք չէ. Contact էջը օգտագործում է `/api/contact`-ը, իսկ ստացող հասցեն դրվում է **Server/.env → CONTACT_TO_EMAIL**։

## Contact form — ինչպես փորձարկել

1. Լրացրու **Server/.env**-ում `send_mail`, `send_mail_password` (Google App Password), `CONTACT_TO_EMAIL`։
2. Գործարկիր `npm run dev` և բացիր `http://localhost:5173/contact`։
3. Լրացրու անուն, քո իրական email և հաղորդագրություն, սեղմիր «Ուղարկել հաղորդագրությունը»։
4. Հաջողության կանաչ հաղորդագրությունը կհայտնվի էջում, իսկ `CONTACT_TO_EMAIL` հասցեին կգա նամակ։ Կարող ես սեղմել **Reply**՝ անմիջապես հաճախորդին պատասխանելու համար։
5. Եթե SMTP տվյալները սխալ են, կհայտնվի կարմիր սխալ, և Backend-ի terminal-ում կերևա դրա պատճառը։

Backend-ը սահմանափակում է հաճախակի ուղարկումները (5 հաղորդագրություն/ժամ մեկ IP-ից), ստուգում է տվյալները և HTML-ի ներմուծումը։ Դիմումի տվյալները MongoDB-ում չեն պահվում։

## API

Բոլոր `/api/shop` endpoint-ները պաշտպանված են JWT session cookie-ով և վերադարձնում են տվյալ մուտք գործած օգտատիրոջ տվյալները։

| Endpoint | Նպատակ |
| --- | --- |
| `POST /api/contact` | Ուղարկել նամակ Contact էջից (առանց login-ի, body `{ "name": "...", "email": "...", "message": "..." }`) |
| `GET /api/shop` | Ստանալ անձնական favorites/cart |
| `PUT /api/shop/favorites/:id` | Պահել նախընտրածը |
| `DELETE /api/shop/favorites/:id` | Հեռացնել նախընտրածից |
| `DELETE /api/shop/favorites` | Մաքրել նախընտրածները |
| `POST /api/shop/cart/:id` | Ավելացնել զամբյուղ (+1) |
| `PATCH /api/shop/cart/:id` | Փոխել քանակը, body `{ "quantity": 2 }` |
| `DELETE /api/shop/cart/:id` | Հեռացնել զամբյուղից |
| `DELETE /api/shop/cart` | Մաքրել զամբյուղը |

**Կատալոգը պահվում է MongoDB-ում** և խմբագրվում է `/admin` էջից։ Նախկին 4 դեմո ապրանքները ներմուծվում են միայն առաջին գործարկման ժամանակ։ Զամբյուղը վճարման կամ պատվերի հաստատում չէ. վճարումներ ավելացնելուց առաջ անհրաժեշտ է server-side checkout և order գործընթաց։

## Ստուգման սցենար

1. Բացիր գլխավոր էջը, որպես հյուր սեղմիր ցանկացած ապրանքի սրտիկը կամ զամբյուղի կոճակը. պետք է բացվի Մուտքի էջը։
2. Գրանցվիր, հաստատիր Email-ը Nodemailer-ի նամակի հղումով, հետո մուտք գործիր։
3. Կրկին սեղմիր ապրանքի կոճակը։
4. Header-ի «Իմ էջը» → Նախընտրածներ կամ Զամբյուղ. տվյալները պետք է երևան այնտեղ։
5. Փոխիր քանակը, թարմացրու էջը, դուրս եկ, կրկին մուտք գործիր. պահպանված ապրանքները պետք է մնան։
6. Մուտք գործիր երկրորդ օգտատիրոջ հաշվով՝ առաջինի ընտրված ապրանքները չպետք է երևան։

**Նշում․** Ժամանակակից React/Vite package-ները տեղադրվում են `npm install` հրամանով։ Եթե տվյալների բազան կամ SMTP-ը միացված չեն, գրանցման ընթացքը չի աշխատի, մինչև `.env` արժեքները և ծառայությունները ճիշտ չկարգավորվեն։

**Նշում․** Արտադրական միջավայրում (production) SMTP-ը պետք է տեղակայված սերվերից հասանելի լինի, իսկ frontend-ի `VITE_API_URL`-ը պետք է մատնանշի այդ Backend-ը։ `FRONTEND_URL`-ն էլ դարձրու կայքի իրական HTTPS հասցեն։


## `/api/auth/me` — 401-ի ուղղում

Երբ հյուրն առաջին անգամ բացում է կայքը, frontend-ը կանչում է `GET /api/auth/me`։
Այժմ այս հարցումը **200** է վերադարձնում, եթե օգտատերը մուտք չի գործել՝

```json
{ "user": null, "authenticated": false }
```

Մուտք գործած օգտատիրոջ դեպքում նույն հարցումը վերադարձնում է
`{ "user": { ... }, "authenticated": true }`։ Ժամկետանց կամ անվավեր cookie-ն
մաքրվում է և օգտատերը համարվում է հյուր։ Մասնավոր `/api/profile` և `/api/shop`
հարցումները **շարունակում են պահանջել JWT** և առանց մուտքի վերադարձնում են 401։

Եթե մուտք գործելուց հետո էլ կայքը չի ճանաչում քեզ, ստուգիր՝
`Server/.env` → `FRONTEND_URL=http://localhost:5173`,
`Client/.env` → `VITE_API_URL=http://localhost:3000`,
և օգտագործիր **միևնույն** `localhost` hostname-ը (ոչ թե մի տեղ `127.0.0.1`,
մյուս տեղ `localhost`)։ Backend-ն ու Frontend-ը վերագործարկիր `.env`-ի փոփոխությունից հետո։

## 🔐 Առանձին Admin Panel — առանձին հաշիվ և գաղտնաբառ

Կառավարման վահանակ՝ **http://localhost:5173/admin**, մուտք՝ **http://localhost:5173/admin/login**։
Այստեղ կան Dashboard, Products, Users էջեր, և երեք լեզու՝ հայերեն, ռուսերեն, անգլերեն։

**Այս տարբերակում ադմինի հաշիվը լիովին անկախ է սովորական խանութի օգտատերերից։** Այն պահվում է MongoDB-ի
առանձին `adminaccounts` հավաքածուում, ոչ թե `users` հավաքածուում։ Նույն Email-ով գնորդ գրանցելը ադմինի իրավունք **չի տալիս**։
Սովորական գրանցումը, email verification-ը կամ `admin:grant` հրամանը ադմինի հաշիվ ստեղծելու համար անհրաժեշտ չեն։

### 1․ Առաջին ադմինի ստեղծում (միայն վստահելի համակարգչից)

Առաջին հերթին կարգավորիր `Server/.env`-ը. հատկապես `MONGO_URL`/`MONGODB_URI` և `JWT_SECRET`։
Բացիր **Windows CMD կամ PowerShell** նախագծի գլխավոր պանակում՝

```cmd
cd C:\Users\Admin\Desktop\Shop.project
npm install
npm run admin:create -- gabrielyanarsho3@gmail.com
```

Ծրագիրը կխնդրի երկու անգամ մուտքագրել **քո ընտրած նոր գաղտնաբառը** (առնվազն 12 նիշ, առավելագույնը 72 բայթ)։
Հավաքելիս գաղտնաբառը չի երևում էկրանին. դա նորմալ է։ Գաղտնաբառը **մի գրիր հրամանի կամ `.env` ֆայլի մեջ**։
Գաղտնաբառը MongoDB-ում պահվում է միայն `bcrypt` հեշով։ `admin:create`-ը նույն Email-ով կրկնակի հաշիվ չի ստեղծի։

### 2․ Բացիր Admin Panel-ը

```cmd
npm run dev
```

Բացիր **http://localhost:5173/admin/login**, մուտքագրիր վերը նշած Email-ն ու նոր գաղտնաբառը։
Սովորական խանութի Login-ը **չի** մուտք գործում ադմինիստրատորի էջ։

### 3․ Փոխել մոռացված գաղտնաբառը

```cmd
npm run admin:password -- gabrielyanarsho3@gmail.com
```

Տեղային ինտերակտիվ terminal-ը կառաջարկի երկու անգամ մուտքագրել նոր գաղտնաբառը։
Փոխելուց հետո **բոլոր նախկին Admin JWT-ները անվավեր են**։

### Անվտանգություն

- Ադմինի մուտքը հասանելի է միայն նախապես ստեղծված `AdminAccount` գրառումներով։ Հրապարակային `/admin/register` չկա։
- Գաղտնաբառերը `bcrypt`-ով են, իսկ JWT-ը՝ հատուկ 12 ժամանոց `phoneshop_admin_session` HttpOnly cookie-ում (`/api/admin` ուղի)։
- Սովորական հաճախորդի `armauth_session` cookie-ն **երբեք** չի օգտագործվում ադմինի API-ի համար։
- Յուրաքանչյուր ադմին հարցման ժամանակ ստուգվում է AdminAccount-ի ակտիվ լինելը և token-ի `sessionVersion`-ը։
- Խանութի ապրանքների կառավարումն ու վիճակագրության endpoint-ները շարունակում են պահանջել ադմինի JWT։
- Իրական կայքի համար օգտագործիր HTTPS, ուժեղ գաղտնաբառ, պահիր Server-ի `.env`-ը գաղտնի և սահմանափակիր սերվերի հասանելիությունը։

### Ինչ է հնարավոր անել ադմինի էջում

- Dashboard՝ օգտատերերի, ապրանքների, զամբյուղների վիճակագրություն, վերջին գրանցումներ։
- Products՝ ավելացնել, խմբագրել, հեռացնել, փոխել գին, պահեստային քանակ, նկար և այլն։
- Users՝ որոնել գնորդներին, տեսնել email հաստատումը և Cart/Favorites վիճակագրությունը, առանց գաղտնաբառերը դիտելու։
- `admins` վիճակագրությունը հաշվում է **առանձին ակտիվ ադմիններին**, ոչ թե գնորդների դերը։

**Նշում.** Նախկին `admin:grant`/`admin:revoke` հրամանները հեռացվել են, որովհետև այստեղ ադմինները այլևս սովորական User գրառումներ չեն։
Դրանց փոխարեն օգտագործիր `admin:create` և `admin:password`։

Այս նախագիծը իրական վճարումներ և պատվերի հաստատում դեռ չի կատարում։

## Գաղտնաբառի վերականգնում (նոր)

- Մուտքի էջից «Մոռացե՞լ ես գաղտնաբառը» → `/forgot-password`։
- `POST /api/auth/forgot-password`՝ email + language։ Հաստատված հաշիվներին ուղարկվում է 1 ժամ գործողությամբ, մեկանգամյա հղում։ Անհայտ email-ների դեպքում պատասխանը նույնն է, որպեսզի հաշիվները չբացահայտվեն։
- Նամակի հղումը `/reset-password?lang=hy#token=...` ձևաչափով է։ Գաղտնի token-ը պահվում է միայն SHA-256 հեշով DB-ում։
- `POST /api/auth/reset-password`՝ token + password։ Նոր գաղտնաբառը պահպանվում է bcrypt հեշով, token-ը ոչնչացվում է, բոլոր նախկին օգտատիրական սեսիաներն անվավեր են դառնում։
- Անհրաժեշտ են **աշխատող MongoDB, SMTP_USER/SMTP_PASS և FRONTEND_URL**։ Տեղային և Vercel միջավայրերում կարգավորիր նույն env փոփոխականները։
- Backend-ում rate limiting-ը կանխում է զանգվածային հարցումները։ Վերականգնումը վերաբերում է **հաճախորդի հաշիվներին**, ոչ թե admin account-ին (admin-ի համար արդեն կա `npm run admin:password`)։
- Անվտանգության համար այս ZIP-ում չկան `.env`, `.git` և `node_modules` պանակները։ Նախկին `Server/.env`-ը պահիր առանձին, օգտագործիր `Server/.env.example` որպես օրինակ։
